## 0. 왜 재개인가

slice v1은 기술적으로 완주했으나 플레이 판정 세 항목이 모두 실패했다.

| 검증 항목                  | v1 결과                             |
| -------------------------- | ----------------------------------- |
| 하루 소요 시간             | 30초 미만 — 텍스트를 읽지 않고 통과 |
| 트리아지가 고민을 만드는가 | 아니오 — 위에서부터 찍음            |
| 완곡어를 스스로 알아채는가 | 아니오                              |

세 실패는 하나의 원인을 공유한다: **"이 선택이 어떤 의미인지 알기 어려웠다."**
버리는 쪽에 비용이 있다는 인지가 없었고, 버린 것이 나빠졌다는 확인도 없었다.
노후도는 내부적으로 틱하고 있었으나 플레이어에게 보인 적이 없다 — **안 보이는 수치는 없는 수치다.**
읽을 이유가 없는 텍스트의 변형은 알아챌 수 없으므로, 완곡어 실패는 앞 두 실패의 결과다.

### 기각된 처방: 중요 문구 강조 표시

완곡어 시스템의 명제는 "같은 문장이 기억에 따라 다르게 읽힌다"인데, 볼드는 "이 문장이 중요합니다"라는
**저자의 지시**다. 앞은 독자의 인식 변화, 뒤는 저자의 개입이라 뒤를 넣으면 앞이 성립하지 않는다.

- 기억 0의 신입이 완곡어를 굵게 본다면 그는 이미 완곡어를 액면대로 읽는 사람이 아니다
- 드라마틱 아이러니의 위치가 "나와 돌아온 자 사이"에서 "플레이어와 게임 사이"로 이동한다
- 실용적으로도 역효과 — 강조를 치면 강조된 것만 읽는다

변화의 전달은 문장 **안**이 아니라 **밖**에서 해결한다 (§4 카드 이중 구조, §7 재열람).

### 같은 이유로 기각: 재발부 횟수 표기

세션 2 구현 시 재발부 카드에 "재발부 N차"를 표기했으나 **제거한다.**
방치했던 카드가 돌아올 때 화면이 먼저 알려주면 그것은 놀람이 아니라 **통보**이며,
강조 표시와 정확히 같은 종류의 개입이다. 검증 목표 1은 "저거 내가 넘긴 건데"가
**플레이어의 문장**으로 오는지를 묻는 것이지, UI가 대신 말해주는지를 묻는 것이 아니다.
난이도 보정(`cardNeglect` 기반 가산)은 유지하되 표기만 뺀다.
조직 언어 안에 녹이는 방식(재접수 서식 번호 등)은 허용한다 — 읽어야 알 수 있으면 통보가 아니다.

## 1. 검증 목표

기능 완성도가 아니라 **판정 통과**가 목적이다. 계측·지표는 넣지 않는다 (첫 지표는 Phase 1의 D7 재방문).

1. **놀라는가** — 어제 넘긴 것이 악화된 채 돌아왔을 때 "저거 내가 넘긴 건데"가 오는가
2. **읽는가** — 카드를 열고 산문을 읽는가. 하루 소요 시간이 유의미하게 늘었는가
3. **알아채는가** — 기억 1 이후 서류함에서 WO-T3를 다시 열었을 때 **스스로** 발견하는가
4. **금요일이 무서운가** — 주간 평가가 주중의 선택에 압박을 만드는가

**1~3에서 실패하면 4주로 넘어가지 않는다.** 30초짜리 하루를 20번 반복하는 것에 불과하기 때문이다.

목표 3의 통과 조건은 "달라진 것을 맞히는가"가 아니라 **"확신하지 못한 채 다시 읽게 되는가"**다.
자기가 잘못 기억하는 것인지 문서가 달라진 것인지 헷갈렸다면 그것은 통과다 (§7).

추가 판정: **조우를 3~4회 겪고도 매 턴 선택이 고민이 되지 않으면 조우를 재설계한다** (§6).

### 놀람의 설계 기준: 크기가 아니라 귀속

놀라야 할 것은 "세상이 나빠졌다"가 아니라 **"저거 어제 내가 넘긴 거다"**이다.
전부가 똑같이 나빠지면 아무것도 내 탓이 아니고 그냥 세계관이 된다. 따라서 **대비**가 핵심이다.

- 처리한 것 → 눈에 띄게 내려간다 (내 손이 닿은 흔적)
- 방치한 것 → 기본 틱 이상으로 올라간다

놀람은 음량이 아니라 인식에서 나온다. 경고창·붉은 텍스트는 톤 기준 위반이며 불필요하다.
어제 본 문장과 같은 자리에 있는데 한 단어만 다를 때 — 완곡어가 이미 쓰는 근육을 축만 바꿔 쓴다.

## 2. 시간 구조와 주간 평가

- **5근무일 + 2일 휴식 = 1주**
- `world.calendar {day(주말 포함 통산), weekday 1~5}`, 금요일 종료 시 주말 경과(day+3)
- 금요일 종료 시 본부의 **주간 평가**: `완벽 / 양호 / 염려 / 경고` → `world.weekRatings`에 기록
- 4주 = 1사이클, 사이클 종료 시 승진·해고 판정 — **범위 밖.** 이번엔 평가 1회만 본다
- 실시간 액션 게이트는 오프 (Phase 1에서 활성화)

### 피드백 층

배치 주기 구조상 구역 복귀는 이번 범위에 없다. 따라서 1주차의 피드백은 두 층이다.

| 층       | 단위 | 주기 | 역할                                                         |
| -------- | ---- | ---- | ------------------------------------------------------------ |
| **미시** | 카드 | 1일  | 어제 넘긴 카드가 악화된 채 오늘 다시 올라온다. 주 3~4회 발생 |
| **주간** | 평가 | 5일  | 주중의 누적이 하나의 등급으로 돌아온다                       |

### 평가식은 슬라이스 한정 임시식이다

현재 평가 = 금요일 종료 시점 배치 구역의 노후도 밴드이며, 별도 산식이 없다.
플레이어가 보는 것과 평가받는 것이 같아야 인과가 짧기 때문이다.

**단, 이 때문에 검증 목표 4가 목표 1·2와 같은 것을 묻게 된다.**
평가가 밴드의 사본이면 "금요일이 무섭다"는 "노후도가 무섭다"와 구별되지 않는다.
밴드에서 파생되지 않는 항(보고 누락, 다일 이벤트 미제출, 주목 등)을 섞는 안건이 열려 있다
(`docs/open-questions.md` A). **1주차 판정 이후에 결정한다** — 지금 고치면 판정이 측정하려던 것을
측정하지 못한다.

### 고도의 위치 (확정)

**고도는 실패 상태가 아니다.** 게임오버로 연결되지 않으며, "그 존재"의 부활과도 무관하다.
일과 실패의 압박은 **조직의 인사 관리(주간 평가·해고)가 전부 흡수한다** — 고도가 압박까지 맡으면
실패 경로가 이중이 되고, 승진=벌 구조가 "고도 방어 게임"으로 납작해진다.

따라서 **주간 루프 UI(원장·일일 정산)에 고도를 표기하지 않는다.**
내부 수치·산식은 유지하되 에피소드 스케일 장치(남은 시간의 감각)로만 쓴다.
노후도가 고도를 갉는다는 서술은 유효하다. 다만 그것은 플레이어가 관리하는 게이지가 아니라
**세계가 기울고 있다는 사실**이다.

> **참고(범위 밖):** 승진하면 이전 구역으로 복귀하지 않는다. 대신 떠난 구역의 **소식이 회람되고**,
> 그 구역의 노후도가 도시 고도를 계속 갉는다. 돌아갈 수 없다는 것이 약점이 아니라 무기다 —
> 확인할 수도, 고칠 수도 없다. 4주 사이클 설계 시 이 절을 확장한다.

## 3. 구역 노후도

내부 수치 `0~10` 유지, **렌더링만 4밴드로 접는다.** 밴드는 저장하지 않는 파생값이다.

| 밴드 | 범위 | 이름   | 가시성                          | 주간 평가 |
| ---- | ---- | ------ | ------------------------------- | --------- |
| 1    | 0~2  | 정상   | 이상 없음                       | 완벽      |
| 2    | 3~5  | 삐걱임 | 미묘한 묘사 결만                | 양호      |
| 3    | 6~8  | 이상   | **임계 — 여기서부터 확인 가능** | 염려      |
| 4    | 9~10 | 한계   | 숨길 수 없음                    | 경고      |

밴드 이름은 **확정**이다 (가안 아님).

### 임계 = 3밴드 진입

- **신호 대 잡음.** 매일 조금씩 달라지는 묘사는 오히려 못 알아챈다.
  아무 일 없다가 어느 날 달라져 있어야 놀람이 발생한다
- **테마 일치.** "임계를 넘어야 보인다"는 이 도시가 무너지는 걸 아무도 모르는 이유 그 자체다
- **확장 자리.** 감류/공명 등급이 오르면 임계가 내려간다 — 남들보다 먼저 본다.
  **이번엔 만들지 않고 자리만 비워둔다**

### 수치 (슬라이스 강제값)

정식 곡선은 Phase 1 문제다. 이번엔 **판정이 반드시 발생하도록** 역산한 값을 쓴다.

- 시작 노후도 `4` (2밴드 상단)
- 자연 틱 `+1/일`
- 카드마다 **가중치 `1~3`** (빌드 검증이 강제). 노후도 5 시점 제시 4장의 가중치 합 = `8`
- 처리 성공: 가중치만큼 `−`
- 방치: 가중치만큼 `+`

일일 변화 폭은 대략 `-1 ~ +3`. 5일 후 도달 범위는 `0 ~ 10`(clamp).
**최선의 플레이만 1밴드에 닿는다** — 완벽 평가가 실제로 어렵도록.

### 정산 규칙 (확정)

- **노후도 증감은 전부 CLOSE_DAY 가중치 정산의 몫이다.** 콘텐츠 효과에 구역 decay를 두지 않는다
  (이중 계산 금지 — 빌드 검증이 아니라 콘텐츠 정합 테스트로 강제). 정석/임시방편의 차이는
  난이도·플래그·메나스로만 표현한다
- **처리 성공 = −가중치 / 처리 실패 = `0` / 방치 = +가중치 / 자연 틱 = +1**
- **하루치를 합산한 뒤 1회만 클램프**(0~10). 항목마다 클램프하면 순서에 따라 결과가 달라진다

> **실패가 0인 것이 중요하다.** 실패에 페널티를 얹으면 플레이어가 어려운 카드를 피하게 되고
> 트리아지가 "안전한 것부터"로 붕괴한다. 실패의 대가는 **못 한 다른 일**이다.

> **가중치가 핵심이다.** 가중치가 없으면 "2장 처리 / 2장 방치"가 고정이라 무엇을 고르든 결과가 같다.
> 가중치가 있어야 "큰 것을 고쳐 평가를 지킬 것인가, 작은 것을 골라 다른 것을 얻을 것인가"가 성립한다.
> 후자의 보상이 §5의 배타적 선택 이벤트다.

## 4. 카드 이중 구조

카드는 일상 지시서와 서사 사건을 **모두** 대표한다. 핵심은 층을 나누는 것이다.

- **표면 층 = 업무 분류 (카드 얼굴).** 전부 조직의 언어
- **실제 층 = 열었을 때 벌어지는 일.** 일상 처리 / 서사 사건 / 설비 이상 조우 / 이상현상

### 분류는 스키마의 명시 필드다

표면 분류는 **확정 5종**이며 늘리지 않는다:
**점검 / 순찰 / 보고 / 자재 / 탐사.**

얼굴 문구("정기 순시", "조직 방문·보고", "미확인 구간 확인" 등)는 그 분류 안의 **표현 변형**이다.
문구는 늘려도 분류는 5개로 고정된다.

**검증기는 문자열이 아니라 분류 필드를 검사한다.** 그래야 "전투 같은 얼굴 거부"가
문자열 휴리스틱이 아니라 타입으로 닫히고, 아이콘 일대일 대응(어휘 크기 = 분류 수 5)이
추론 없이 성립한다. 아이콘의 대응 대상은 분류 필드이지 얼굴 문구가 아니다.

### 규칙: 표면은 실제를 예고하지 않는다

- **표면 층에 "전투"를 두지 않는다.** 카드가 전투를 미리 알리면 이 도시는 몬스터의 존재를
  공식 인정하는 도시가 된다. 확정 설정상 그것은 "설비 이상"이고 조우 보고서는 고장 신고서 양식이다.
  침묵의 유지가 세계관의 토대다
- **상점·보상은 실제 층에 두지 않는다.** 그것은 결과지 사건의 정체가 아니다

### 이 구조가 해결하는 것

1. **표지를 열게 만든다.** "점검"이 대부분 그냥 점검이고 가끔 열면 배관이 숨 쉬고 있으므로,
   플레이어는 모든 카드를 열게 되고 열면 산문을 읽는다 → 검증 목표 2
2. **완곡어가 카드 층에서 작동한다.** 카드 제목은 수십 번 다시 보는 물건이다.
   "간헐 명멸"을 열 번 처리한 뒤 어느 날 제목이 달라져 있으면 볼드 없이 눈에 박힌다 → 검증 목표 3
3. **기억이 오르면 표면을 의심하기 시작한다.** 신입은 "미확인 구간 확인"을 액면대로 읽고,
   기억 3의 나는 그 단어를 보면 긴장한다. 카드 얼굴은 그대로인데 읽는 사람이 변한다

### 하루의 구성

- 배치 구역 **1곳**(1주차 `d5` 고정)에서 **최대 4장** 제시, **처리 2장.**
  남은 카드는 방치되어 미시 피드백으로 돌아온다
- **제시 장수는 노후도에 따른다.** Day 1(노후도 4)은 3장으로 시작한다 —
  **도시가 나빠질수록 책상이 붐빈다**
- 제시 순서 = 방치 누적 큰 순 → `minDecay` 깊은 순. rng는 완전 동률일 때만 개입 —
  **무작위성의 출처가 셔플이 아니라 도시 상태다**
- **방치 미시 피드백**: `world.cardNeglect` 장부. 방치 시 +1, 처리 성공 시 리셋.
  재발부 카드는 난이도 보정을 가산한다 (표기는 하지 않는다, §0)
- 덱빌딩·손패·이월 카운터는 넣지 않는다. "쌓인 카드"와 "노후도"가 같은 것을 두 번 세게 되어
  수치 이중화가 발생한다 — 1인이 관리하기 나쁜 종류의 복잡도

### 판정 정보는 공개한다

선택지에 **판정 기술·스탯명과 성공률(%)을 표기한다.**
트리아지가 고민이 되려면 저울에 눈금이 있어야 한다 — 확률을 가리면 선택이 감이 되고,
감으로 고른 것은 후회로 남지 않는다.

**비공개 대상은 노후도 수치 하나뿐이다.** 밴드만 보이고 정확한 값은 보이지 않는다.
§9의 "선택 전 정보 제공 금지"는 이 한 항목에 한정되며 판정 정보로 확대하지 않는다.

## 5. 이벤트 구조

### 필수 / 선택의 배타성

- **필수 이벤트**(진실에 도달하는 뼈대)는 피로·동요·주목을 잘 관리하면 **전부 볼 수 있다**
- **배타성은 선택 이벤트 쪽에 있다** — 동료의 부탁, 이웃의 일, 길가의 꽃 한 송이 같은 것들

이 배치가 중요한 이유: "잘하면 다 볼 수 있다"를 필수 쪽에 두면 최적해가 존재하는 위키 게임이 되고,
"모든 것을 고칠 수 없다"는 제약을 메커니즘이 반박한다. 버리는 것을 **필수에서 선택으로 옮기면**,
완주 플레이어는 진실을 다 알고도 아무와도 가까워지지 못한 채 끝난다.
"무엇을 놓아줄 것인가"가 성립하고, 테마 3번이 정확히 여기서 작동한다.

### 다일 이벤트 (최대 3일)

- 선택 **즉시 3근무일 점유를 선언**한다. 5일 중 3일이 사라지므로
  **"이번 주를 이것에 걸겠다"는 선언**이 된다
- 점유일의 근무 슬롯 2 → 1. 방치가 3장까지 쌓여 노후도가 급등하고 주간 평가가 떨어진다.
  **필수를 쫓을수록 평가가 떨어지는 압박이 시간표에서 저절로 나온다**
- **드물게.** 4주 사이클 기준 1~2회. 매주 하나면 그냥 주간 메인 퀘스트가 되고 선택이 아니게 된다
- Pathfinder식 촘촘한 기한 시스템은 도입하지 않는다 — 시간표 관리 게임이 된다
- **1주차 슬라이스에는 EV-002(돌아온 자의 사흘 부탁) 1개만** 배치하여
  트레이드오프가 실제로 아픈지 확인한다

## 6. 조우 (설비 이상)

**다단 조우.** 구현값은 **4행동 × 최대 4턴**이다.

- **관찰** — 태우기·재우기 난이도 −1/회
- **진정** — 누적 2회로 잠듦
- **태우기** — 성공 즉시 회수
- **물러서기** — 이탈
- 턴 소진 시 강제 이탈. **새 자원 0개** — 피로·동요·기술 등급 등 기존 스탯만 쓴다

### 정산

- 태움·재움 = **처리 성공**(−가중치)
- 물러섬·턴 소진 = **처리 실패**(시간만 잃는다, 노후도 0)
- 결말 축 플래그가 남는다: `enc_burned_*` / `enc_soothed_*`

이 플래그는 굿 엔딩 조건 2(화염술·빙결술 숙련)의 데이터원 후보다
(`docs/open-questions.md` B — 숙련을 조우에서만 오르게 묶는 안).

### 입구

- **WO-T5(미확인 구간 확인, `minDecay 6` = 3밴드 임계).**
  노후도가 임계를 넘어야만 온다 — 도시가 나빠진 결과로만 조우가 발생한다
- 카드 안에 **조우 회피 옵션**(접근 제한 표지)이 있어 진입 자체가 선택이다
- **드물게 나오되 나올 때 무겁게.** 매일 나오면 "설비 이상"이라는 완곡어가 우스워지고
  도시의 침묵이 성립하지 않는다. **1주차에 1회**

### 격리 원칙 (구현 확정)

조우 상태는 GameState 밖 **독립 리듀서**(`core/encounter.ts`)의 로컬 상태다.
종료 시 outcome별 효과만 `RESOLVE_ENCOUNTER` 액션으로 반입한다.
**조우 안에서 세계 상태를 직접 건드리지 않는다** — 향후 본격 전투 시스템으로 전환할 때
그 리듀서만 교체하면 되고, 섞이면 전환이 리팩터링 규모가 된다.

- **제약**: 조우 상태는 저장되지 않는다. 조우 중 새로고침 시 조우만 초기화된다.
  슬라이스의 의도적 단순화이며 4주 확장 시 재검토
- **재설계 판정**: 조우를 3~4회 겪고도 매 턴 선택이 고민이 되지 않으면 재설계한다.
  턴 4 / 진정 임계 2 / 관찰 보정 1은 전부 가안이며 실측 후 확정
  (`docs/open-questions.md` C)

> 본격 전투 도입은 "텍스트 기반 일상 시뮬"이라는 장르 정의를 다시 여는 결정이므로 별도 안건.

## 7. 텍스트 변형 축 분리 원칙

변형 축이 둘(`기억` × `노후도`)이 되면 조합이 폭발한다. 0~10 × 0~7 = 한 문서에 88개 변형은 쓸 수 없다.

1. **노후도는 4밴드로 접어서만 렌더링에 쓴다** (내부 수치는 0~10 유지)
2. **두 축을 한 문서에서 동시에 쓰지 않는다**
   - 완곡어(`기억`) → 문서·보고서·카드 표면 텍스트
   - 악화(`노후도` 밴드) → 현장 묘사·카드 본문

이 원칙은 **콘텐츠 테스트가 강제한다.** 템플릿 본문 변형 조건에는 `{zone}` 치환자를 허용하며
바인딩 시점에 구체화된다.

### 재열람

강조 대신 **재열람**을 넣는다. **강조는 답을 주고, 재열람은 질문을 준다.**

- **`world.archive`** — 제시된 카드 / 읽은 면담록 / 겪은 조우를 기록한다. 본문은 저장하지 않고 중복도 없다
- **서류함 UI에서 보관 문서를 현재 상태로 재렌더링한다.**
  3주차에 1주차 지시서를 열면 그때 읽은 것과 다른 문장이 나온다 —
  **문서가 바뀐 것이 아니라 내가 달라진 것**
- **기억 상승 시 알림은 한 줄, 내용은 말하지 않는다.**
  "기억이 남았다 (N/7). 서류함의 옛 문서를 다시 열 수 있다."
  무엇이 달라졌는지는 알리지 않는다
- 목록의 카드 제목도 현재 `기억`으로 렌더링된다. 아이콘은 앵커이므로 불변이며,
  과거 줄들의 제목만 조금씩 달라진 채 같은 아이콘이 세로로 반복된다
- **노후도는 재열람에 개입하지 않는다.** 지시서는 문서이므로 `기억` 축 전용

### 구현 제약 (상시 유효, 세이브 스키마 변경 시마다 재확인)

- **렌더링된 문장을 저장하지 않는다.** 세이브에 완성된 문장이 들어가면 재렌더가 슬그머니
  보관본이 된다. 저장 대상은 문서 ID와 상태값뿐이다
- **과거 문서에도 현재 `기억`을 적용한다.** "그때 값으로 렌더링"이 자연스러운 구현이므로
  명시하지 않으면 나중에 그쪽으로 고쳐진다. **테스트로 고정한다**

보관본 방식(그날 문장을 저장해 나란히 비교)은 채택하지 않는다. 보관본은 증거를 손에 쥐여주지만,
재렌더는 증거를 주지 않는다. 자기가 잘못 기억하는 것인지 문서가 달라진 것인지 확신할 수 없는 상태가
**이 도시에 사는 감각 그 자체**다.

**1주차 판정 범위에서 재열람에 비용을 붙이지 않는다.** 피로 등을 물리면 측정하려는 행동 자체를
억제한다. 무료로 열어두고 그래도 안 보는지를 먼저 본다 — 안 본다면 비용 문제가 아니라
**되돌아볼 이유가 없다는 문제**이며 다른 곳을 고쳐야 한다.

## 8. 상태 모델

기존 3시트 구조(`account:*` / `self:*` / `world:*`)를 그대로 쓴다.

```
world:zones.<id>.decay           number 0~10    구역 노후도 (ID: d2/d5/d7, 고유명사 미정)
world:assignment.zone            zoneId         현재 배치 구역 (1주차 d5 고정)
world:calendar.day               number         통산 일차 (주말 포함)
world:calendar.weekday           number 1~5     주중 일차
world:weekRatings.<n>            enum           주간 평가 결과
world:cardNeglect.<id>           number         방치 누적 (미시 피드백·난이도 보정)
world:multiday.active            {id, daysLeft} 다일 이벤트 점유
world:archive                    docId[]        재열람 대상 (본문 미저장, 중복 없음)
self:memory                      number 0~7     기존 — 완곡어 게이트
```

- 밴드는 저장하지 않는다. `decay → band`는 렌더링 시점의 파생 함수
- 카드 가중치는 콘텐츠 스키마의 정적 필드 (`weight: 1~3`), 빌드 검증이 강제
- 카드 표면 분류도 정적 필드 (5종 enum), 검증기가 이 필드를 검사 (§4)
- 조우 상태는 `world:*`에 섞지 않고 별도 리듀서 로컬 상태 (§6)
- **세이브는 `{schema, state}` 봉투.** 불일치 시 새 게임. 현재 `SAVE_SCHEMA 3`

## 11. 구현 현황 (세션 분할 — 전부 완료)

1. **시간·평가 코어** ✅ — 5근무일 + 주말, `world.calendar`, 노후도 틱/가중치/밴드 파생, 금요일 평가

4. **완곡어 렌더링 확장** ✅ — 축 분리 원칙 적용, 재열람·서류함
