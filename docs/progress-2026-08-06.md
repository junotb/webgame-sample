## 2. Project Instructions에 반영 필요한 확정 사항

구현 과정에서 결정되어 v3 문서에는 기록했으나, 설계 원본(Claude Project)에 아직 없는 것들.

1. **가제 확정**: "내일도 난 여기에 / Still Here Tomorrow"
2. **상태 키 표기**: `world:districts.*` → `world:zones.*` 리네임. 치환자도 `{district}` → `{zone}`.
   구역 ID 값(d2/d5/d7)과 고유명사 체계는 여전히 미정
3. **노후도 정산 규칙** (v3 §3 구체화):
   - 노후도 증감은 **전부 CLOSE_DAY 가중치 정산의 몫** — 콘텐츠 효과에 구역 decay 금지 (이중 계산 방지)
   - 처리 성공 = −가중치 / **처리 실패 = 0 (시간만 잃음, 방치 아님)** / 방치 = +가중치 / 자연 틱 +1
   - 하루치 합산 후 1회만 클램프 (0~10)
4. **고도의 위치**: 고도는 **실패 상태가 아니다.** 게임오버·"그 존재" 부활과 무관.
   일과 실패의 압박은 조직 인사 관리(주간 평가)가 흡수. 주간 루프 UI에서 고도 표기 제거,
   내부 수치는 에피소드 스케일 장치(남은 시간의 감각)로 보존
5. **판정 정보 공개**: 선택지에 판정 기술/스탯명 + 성공률(%)을 표기하기로 확정.
   v3 §9의 "선택 전 정보 제공 금지"는 노후도 수치에 한정 — 판정 정보는 트리아지 고민의 재료
6. **성장 노티만, 성장 시스템은 없음**: 기술·스탯이 (콘텐츠 효과로) 오르는 순간 로그로 통보.
   **경험치 시스템 신설은 별도 안건으로 이관** — 이 Project에서 결정 필요 (미결)

## 3. 구현 현황 (v3 §11 세션별)

### 세션 1 — 시간·평가 코어 ✅
- `world.calendar {day(주말 포함 통산), weekday 1~5}`, 금요일 종료 시 주말 경과(day+3)
- 노후도 4밴드 파생(0~2/3~5/6~8/9~10, 이름 가안: 정상/삐걱임/이상/한계 — 저장하지 않는 파생값)
- **금요일 종료 시점의 배치 구역 밴드 = 주간 평가**(완벽/양호/염려/경고), `world.weekRatings`에 기록
- 시작 노후도 4, 카드 가중치 1~3 (빌드 검증 강제)

### 세션 2 — 카드 레이어 ✅
- **표면/실제 분리**: 카드 얼굴 5종(점검/정기 순시/조직 방문·보고/자재 수령/미확인 구간 확인).
  "전투" 같은 얼굴은 검증기가 거부 — 표면은 실제를 예고하지 않는다
- 생성기: 배치 구역 1곳(1주차 d5 고정)에서 최대 4장.
  순서 = 방치 누적 큰 순 → minDecay 깊은 순, rng는 완전 동률만 — **무작위성의 출처는 도시 상태**
- **방치 미시 피드백**: `world.cardNeglect` 장부. 방치 +1/처리 성공 리셋.
  재발부 카드는 난이도 보정 가산 + "재발부 N차" 표기
- **다일 이벤트**: 선택 즉시 3일 점유 선언, 점유일 근무 슬롯 2→1 (방치 3장 → 노후도 급등).
  1주차 슬라이스엔 EV-002(돌아온 자의 사흘 부탁) 1개
- 악화 축: 템플릿 본문 변형 조건에 `{zone}` 치환자 허용(바인딩 시 구체화).
  축 분리(§7: 기억 축과 노후도 축을 한 문서에 섞지 않음)는 콘텐츠 테스트가 강제

### 세션 3 — 조우 리듀서 ✅
- **격리 원칙 구현**: 조우 상태는 GameState 밖 독립 리듀서(`core/encounter.ts`) 로컬 상태.
  종료 시 outcome별 효과만 `RESOLVE_ENCOUNTER` 액션으로 반입 → 전투 시스템 전환 비용 최소화
- 4행동 × 최대 4턴: 관찰(태우기·재우기 난이도 −1/회) / 진정(누적 2회 → 잠듦) /
  태우기(성공 즉시 회수) / 물러서기. 턴 소진 = 강제 이탈. **새 자원 0개**
- 정산: 태움·재움 = 처리 성공(−w), 물러섬·소진 = 처리 실패(시간만).
  결말 축 플래그(`enc_burned_*` / `enc_soothed_*`)가 남는다
- 입구: WO-T5(미확인 구간 확인, minDecay 6 = 3밴드 임계) — 노후도가 임계를 넘어야만 온다.
  조우 회피 옵션(접근 제한 표지)도 있어 진입 자체가 선택
- 제약: 조우 상태는 저장 안 됨 — 조우 중 새로고침 시 조우만 초기화 (슬라이스 의도적 단순화)

### 세션 4 — 완곡어 렌더링 확장·재열람 ✅
- `world.archive`: 제시된 카드/읽은 면담록/겪은 조우 기록 (본문 미저장, 중복 없음)
- **재열람**: 서류함 UI에서 보관 문서를 **현재 상태로 재렌더링** — 같은 문서가 기억에 따라 다르게 읽힌다
- 기억 상승 시 알림 한 줄: "기억이 남았다 (N/7). 서류함의 옛 문서를 다시 열 수 있다." —
  무엇이 달라졌는지는 말하지 않는다 (강조는 답을 주고, 재열람은 질문을 준다)

### 부수 작업
- 세이브 스키마 버전 가드 (`{schema, state}` 봉투, 불일치 시 새 게임 — 현재 SAVE_SCHEMA 3)
- 판정 가시화: 선택지 성공률 표기, 원장에 주 스탯 4종·기술 등급 패널

## 5. 다음 단계 — 플레이 판정 (코드 아님)

v3 §1의 게이트: **1~3 실패 시 4주 확장으로 넘어가지 않는다.**

1. 놀라는가 — 방치 카드가 재발부로 돌아올 때 "저거 내가 넘긴 건데"가 오는가
2. 읽는가 — 카드를 열고 산문을 읽는가, 하루 소요 시간이 늘었는가
3. 알아채는가 — 기억 1 이후 서류함에서 WO-T3를 다시 열었을 때 스스로 발견하는가
4. 금요일이 무서운가 — 주간 평가가 주중 선택에 압박을 만드는가

추가 판정 (§6): 조우 3~4회 후에도 매 턴 선택이 고민이 아니면 조우 재설계.
