# UI 화면 규격 — 모바일 가로모드 최우선 · 무스크롤 (2026-08-09)

`phase0-ui-layers.md`의 층위 모델(L0~L4) 위에 얹히는 **화면 규격** 결정.
층의 정의는 바꾸지 않는다 — 각 층이 화면에 놓이는 방식을 확정한다.

---

## 0. 결정

1. **기준 화면은 모바일 가로모드다.** 짧고 넓은 화면(논리 px 약 640~930 × 320~430,
   대표값 844×390)을 기본 스타일로 삼고, 데스크톱은 `min-width`/`min-height`로 **확장**한다.
   지금까지의 반대 방향(데스크톱 기본 + `max-*` 축소)은 폐기.
   모바일에서는 **가로 전용**이다 (2026-08-10 확정) — 세로 진입 시 회전 유도 화면만 띄운다.
2. **스크롤은 발생하지 않는다.** 페이지 스크롤도, 컨테이너 내부 스크롤도 금지.
   **유일한 예외: 이벤트 진행 중의 백로그(이전 텍스트 보기).** 백로그 층 안에서만 스크롤이 허용된다.
3. **긴 본문은 문단 분절로 진행한다.** 엔터·클릭·탭 입력이 다음 문단을 부른다.
   읽기의 박자를 스크롤이 아니라 입력이 만든다.
4. **참고 문법: Type-Moon계 비주얼 노벨** (Fate/stay night, Fate/hollow ataraxia).
   특히 **NVL 방식** — 문단이 화면 전면에 쌓이고, 화면이 차면 장이 넘어간다.

## 1. 왜

- 문서 게임 + 가로 화면은 그대로 두면 스크롤 지옥이다. 가로모드의 실효 높이는 320~390px뿐이고,
  스크롤은 "얼마나 남았는지"를 숨긴 채 읽기를 흘려보낸다.
- VN이 입력 단위로 텍스트를 끊는 이유: **한 번의 입력 = 한 호흡.** 플레이어가 읽기를 소유한다.
- 이 게임의 문서 스킨과 NVL은 이미 같은 구조다 — **종이 위에 문단이 쌓이고, 종이가 차면
  다음 장으로 넘긴다.** 하단 텍스트 창(ADV)을 이식할 필요가 없다. 문서가 곧 텍스트 창이다.
- 정보 밀도 규칙이 따라온다: **한 화면에 들어가지 않는 것은 "더 보여주기"가 아니라 "장 넘김"이다.**

## 2. 층별 적용

| 층 | 적용 |
| --- | --- |
| L0 타이틀 | 이미 한 화면. `100dvh` 고정만 확인 |
| L1 무대 | 상단 띠는 **1줄 고정**(wrap 금지). 지도 높이 = `100dvh − 상단 띠`. 지도+열람 패널 2단 가로 배치는 가로모드의 이상형이므로 유지 |
| L1 열람 패널 | 지시서 본문이 분절 대상. 판정 버튼은 마지막 장에서만 노출 |
| L2 원장·서류함 | 목록도 스크롤 금지 → **장 단위 넘김**(페이지네이션). 서류함 일기는 한 건 = 한 장 이상 |
| L3 오버레이 | 문서 한 장이 화면 안에 들어온다. 개시·정산은 이미 한 화면. 사무소 장면 본문이 분절 대상 |
| L4 통지 | 한 장짜리 공문. 분절 불필요, 화면 안 수납만 보장 |
| 조우 | `log`가 무한히 자라는 현 구조가 최대 위반 지점. **현재 문단만 표시**하고 지난 관측은 백로그로 |

## 3. 백로그 — 유일한 스크롤

- 이벤트(조우·사무소 장면·서사 카드) 진행 중에만 열 수 있다. 지나간 분절을 다시 읽는 층.
- 백로그는 **세션 로컬**이다. 저장하지 않는다 — 조우 상태 미저장과 같은 슬라이스 단순화이고,
  "렌더 문장 미저장" 제약과도 정합(백로그에 쌓이는 것은 표시 이력이지 상태가 아니다).
- 열림/닫힘은 L2 패널 규칙을 따른다: 흐름 위에 겹치지 않고 대신한다.

## 4. 분절의 데이터 표현 — 문자열 배열로 확정 (2026-08-10)

본문(`TextVariant`)의 문단 분절은 **스키마의 문자열 배열**이다. `\n\n` 같은
문자열 안 관례로 표현하지 않는다 — 분절은 읽기의 박자를 정하는 콘텐츠의 명시적 결정이고,
관례는 검증기가 지킬 수 없다.

- 배열 원소 하나 = 문단 하나 = 입력 한 번
- 검증기(`core/validate.ts`)가 검사한다: 빈 배열 금지, 빈 문단 금지, 문단 안 `\n\n` 금지(관례 잔재 차단)
- 스키마 표현: 제목·라벨은 `TextVariant`(한 줄) 유지, 본문·intro만 `ProseVariant`(문단 배열)로 분리
- **세이브 스키마도 오른다 (정정, 2026-08-10 구현 중 발견)** — `WorkOrder.body`가
  `pendingOrders`로 세이브에 들어가므로 SAVE_SCHEMA 6→7. 애초 "오르지 않는다"고 적었던 것은
  틀렸다: 본문 원문은 콘텐츠의 것이지만, 발부된 카드는 그 사본을 상태에 품는다.
  제약 재확인: 문단 배열은 조건+원문 목록이지 렌더된 문장이 아니다 (v3 §8 통과)
- 기존 콘텐츠 본문 전면 이행이 필요하다 — 이행하며 문단 길이를 한 화면(≈390px 높이) 기준으로 재단

### 셸 잠금(7)에서 사양과 갈린 지점

| 사양 | 실제 | 이유 |

## 6. 하지 않는 것

- ADV형 하단 텍스트 창 — 문서 스킨이 곧 NVL 화면이다 (§1)
- 타이핑 연출(글자 단위 출력) — 문단 단위 표시만. 연출은 별도 결정
- 백로그 저장·세이브 스키마 변경 — §3
- **세로모드(포트레이트) 레이아웃 — 가로 전용으로 확정 (2026-08-10).**
  세로 진입 시 회전 유도 화면 하나만 둔다. 세로 레이아웃 작업 라인은 만들지 않는다
