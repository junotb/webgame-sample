## 0. 왜 — 층위가 없다

현재 `web/app/game-view.tsx`의 `GameView`는 아래를 **하나의 `<main>` 세로 스택**에 평면으로 쌓는다.

| 요소 | 현재 위치 | 실제 성격 |
| --- | --- | --- |
| 타이틀 (`STILL HERE TOMORROW / 내일도 난 여기에`) | topbar, 상시 | 게임 **밖**의 것 |
| `DAY 01 · 월 · 특이 사항` | topbar 우측, 상시 | 하루가 열릴 때의 **선언** |
| 도시 운용 원장 | 본문 상단, 상시 | 필요할 때 여는 **참조** |
| 서류함 토글 버튼 | 원장 아래, 상시 | 참조 |
| 단계별 문서 (morning/field/event/closing) | workspace | **지금 해야 할 일** |
| 최근 기록 | 하단, 상시 | 방금 일어난 일의 잔상 |
| 세이브 표시 | 최하단, 상시 | 시스템 |

성격이 다른 일곱 가지가 같은 시각 무게로 세로로 나열되므로 **"지금 봐야 할 것"이 정해지지 않는다.**
가장 중요한 처리 대기 지시서가 화면 중간의 한 블록에 불과하고, 전부 펼쳐진 채라 **카드를 "여는" 행위 자체가 없다.**

이것이 판정에 직접 걸린다. v3 §4는 카드 이중 구조의 효용을 *"표지를 열게 만든다 → 열면 산문을 읽는다"*로
정의했는데, 현 화면은 표지 없이 본문 4장을 동시에 펼쳐 놓는다.
**§4의 전제가 화면에 구현되어 있지 않으므로 검증 목표 2("읽는가")를 지금 측정하면 UI를 측정하게 된다.**

### 그리고 이름이 역할을 오해시킨다

- **`비정규 접촉 기록` / `INCIDENT MEMO`** — 실제로는 스토리렛(EV-001 사무소의 멈춤, EV-002 돌아온 자의
  사흘 부탁)이고, v3 §5 기준 *필수 이벤트 = 진실에 도달하는 뼈대*라 **자주 나오는 것이 의도**다.
  그런데 제목이 사고 보고서라 "위험 경고가 시도 때도 없이 뜬다"로 읽힌다. **프레이밍 오류다.**
- **진짜 경고는 화면에 없다.** `core/reducer.ts`의 `menaceWarnings()`가 메나스 8 도달 시
  로그 한 줄(`⚠ 주목이(가) 한계에 달했다`)을 흘리고 끝이다. 이름을 스토리렛에 뺏긴 채 존재감이 없다.

## 1. 층위 모델

화면을 다섯 층으로 나눈다. **각 층은 "누가 여는가"로 정의된다.**

| 층 | 이름 | 여는 주체 | 내용 |
| --- | --- | --- | --- |
| **L0** | 타이틀 | — (진입점) | 제목, 새 근무 / 이어하기 |
| **L1** | 근무 화면 | 상시 | **구역 지도**(중앙) + 열람 패널 + 최소 상태 |
| **L2** | 참조 패널 | **플레이어** | 도시 운용 원장, 서류함 |
| **L3** | 진행 오버레이 | **게임(흐름)** | 일일 개시, 사무소 장면, 일일 정산, 조우 |
| **L4** | 통지 | **게임(끼어듦)** | 메나스 한계 도달 |

### 규칙

1. **L2와 L3는 동시에 열리지 않는다.** L3가 열리면 L2는 닫힌다 — 참조하다가 흐름에 끌려 들어가는 것은
   되지만, 흐름 위에 참조를 겹치면 다시 지금의 평면이 된다
1. **L3는 L1을 덮고, L2는 L1을 대신한다.** 오버레이 뒤에는 지도가 남지만, 패널이 열리면 무대는
   자리를 비운다 — 아래에 덧붙이면 스크롤해야 보이고 둘이 한 화면에 남아 다시 평면이 된다.
   단 언마운트하지는 않는다: 원장을 잠깐 보고 돌아왔을 때 읽던 지시서가 그대로 열려 있어야 한다
2. **L4만 L3 위에 뜬다.** 드물기 때문에 겹쳐도 혼란이 없고, 겹쳐야 통지의 성격이 산다
3. **L1은 절대 사라지지 않는다.** 오버레이는 L1을 어둡게 덮되 지도는 뒤에 남는다 —
   "사무실을 나간 적이 없다"는 감각
4. 로그(최근 기록)는 층이 아니다. **각 층 안에서 그 층의 결과로만 표시된다** (§6)

## 2. L0 — 타이틀

게임 밖의 화면. 지금 topbar가 들고 있는 것을 여기로 옮기고 **근무 중에는 제목을 표시하지 않는다.**

```
              내일도 난 여기에
          STILL HERE TOMORROW

            ▸ 이어하기  (Day 03 · 수)
            ▸ 새 근무

```

- 세이브가 있으면 `이어하기`가 기본, 없으면 `새 근무`만
- `새 근무`는 기존 세이브를 지우므로 확인 1단계 — 세이브 스키마 불일치 시의 자동 새 게임과 구별
- **부제(`PHASE 0`)는 뺀다.** 개발 단계 표기가 픽션 안에 있을 이유가 없다
- 세이브 로딩 중 표시는 여기서 흡수한다 (현재는 근무 화면 하단에서 `세이브 확인 중`이 깜빡인다)

## 3. L1 — 근무 화면

```
┌──────────────────────────────────────────────────────────┐
│ DAY 03 수        제5구역           잔여 근무 ●●    [원장] [서류함] │
├────────────────────────────────┬─────────────────────────┤
│                                │                         │
│    ⌗                           │   ▸ 열람 패널            │
│  7호 지선                       │                         │
│                        ◇       │   (마커를 가리키면        │
│                      자재 창구  │    지시서가 여기 열린다)  │
│         ▣                      │                         │
│      중앙 관로                  │                         │
│                                │                         │
│  ◉                             │                         │
│ 서편 가로등                     │                         │
│                                │                         │
├────────────────────────────────┴─────────────────────────┤
│                                        [현장 업무 종료 →] │
└──────────────────────────────────────────────────────────┘
```

### 상단 띠 — 상시 노출은 네 가지뿐

`DAY 03 수` / `제5구역` / `잔여 근무 ●●` / 패널 버튼 2개.

- **단계 라벨(`특이 사항` 등)을 띠에서 뺀다.** 지금 `DAY 01 월 · 특이 사항`이 한 덩어리라
  날짜 표시인지 상태 표시인지 모호하다. 단계는 화면이 이미 말하고 있다
- 잔여 근무는 숫자가 아니라 **점 2개**(소진 시 빈 점) — 원장을 열지 않고도 보이는 유일한 수치

### 중앙 — 구역 지도

**배치 구역(1주차 `d5`) 내부의 시설 배치도.** 도시 광역도가 아니다 —
1주차는 한 구역 고정이라 광역도를 띄우면 마커가 한 점에 겹친다.

- 톤은 **조직의 도면**이다. 지형·풍경 묘사가 아니라 배치도·약도. 표면 층의 언어를 지킨다
- 마커 = 오늘 발부된 지시서. 개수는 제시 카드 수(3~4)와 **정확히 일치**
- 처리 완료 마커는 사라지지 않고 **처리 완료 도장 상태로 남는다** — 오늘 무엇을 했는지가 지도에 쌓인다
- **지도는 노후도를 시각화하지 않는다** (§7)

### 우측 — 열람 패널

마커를 **가리키면(hover)** 그 지시서가 여기 열린다.

- **툴팁이 아니라 고정 슬롯이다.** 마커 옆에 붙이면 위치가 마커마다 흔들리고 산문이 들어갈 자리가 없다
- **마우스가 마커를 떠나도 카드는 남는다.** 다음 마커를 가리킬 때 교체된다.
  이래야 마커 → 선택지 버튼으로 커서를 옮기는 동안 카드가 닫히지 않는다
- 호버 진입에 짧은 지연(≈120ms) — 지나가다 열리는 것을 막는다
- 선택지는 카드 안에 있고, **누르는 순간 처리된다.** 별도의 "선택하시겠습니까?" 확인 단계는 두지 않는다:
  선택지 라벨 자체가 이미 "무엇을 할지"이고, 확률·근무 소모가 라벨 아래 붙어 있다
- 아무것도 안 가리킨 상태의 빈 패널 문구: `가리킨 지점의 지시서가 여기 열립니다.`

> **호버로 여는 것이 §4의 "표지를 연다"를 약화시키지 않는가?**
> 열람 비용이 클릭 1회에서 0으로 내려가는 것은 맞다. 그러나 §4가 막으려던 것은 *비용*이 아니라
> **동시 노출**이다 — 4장이 나란히 펼쳐지면 비교·스캔이 되고 산문은 읽히지 않는다.
> 한 번에 하나만 보인다는 제약이 유지되면 §4는 성립한다. 클릭 확정을 얹으면 카드마다 2클릭이 되어
> "일단 다 열어보기"가 억제되는데, 그것은 §7의 재열람 무비용 원칙과 같은 이유로 바람직하지 않다.

### 호버가 없는 환경

터치·키보드는 **탭/포커스가 호버와 같게 동작**한다. 마커는 `<button>`이고 `focus`/`pointerenter`가
같은 핸들러를 공유한다. 호버 지연은 포인터 입력에만 적용한다.

## 4. L2 — 참조 패널 (플레이어가 연다)

### 도시 운용 원장

지금은 본문 최상단에 상시 펼쳐져 있다. **버튼으로 여는 패널로 내린다.**
내용(잔여 근무 / 기억 / 신뢰 / 주 스탯 4종 / 기술 등급 / 메나스 3종 / 구역 노후 밴드 / 다일 점유)은 유지.

- 노후도는 **밴드 이름만** (v3 §3 — 수치는 비공개). 현재 코드는 `제5구역 노후 5`처럼 **수치를 그대로
  노출하고 있다** (`game-view.tsx`의 `zone-row`). **이것은 §9 방어선 위반이며 함께 고친다**
- 고도는 표기하지 않는다 (v3 §2 확정)

### 서류함 — 일기로

현재 `ArchivePanel`은 보관 문서를 **전부 세로로 나열**한다. 그래서 로그창으로 읽힌다.
"이변을 기록해 두고 되짚어 보는 물건"이 되려면 **한 번에 한 건만 펼쳐져야 한다.**

```
┌ 서류함 ───────────────┬──────────────────────────┐
│  01  ⌗  간헐 명멸      │  간헐 명멸                │
│  02  ▣  관로 압력 점검 │  ─────────────────────    │
│ ▸03  ⌗  간헐 명멸      │  (현재 기억으로 렌더된     │
│  04  ◈  사무소의 멈춤  │   본문 한 건)             │
│  05  ◇  자재 수령      │                          │
└───────────────────────┴──────────────────────────┘
```

- 좌: 색인. 보관 순서 = **겪은 순서**. 각 줄은 아이콘 + **현재 기억으로 렌더된 제목**
- 우: 선택한 한 건의 본문. 넘겨보는 행위가 곧 "다시 읽는다"
- **검색·필터·정렬·비교·변경 표시를 넣지 않는다.** v3 §0의 강조 표시 기각 논리가 그대로 적용된다 —
  화면이 "여기가 달라졌습니다"를 대신 말하면 통보가 되고, 목표 3의 통과 조건
  (*확신하지 못한 채 다시 읽게 되는가*)이 성립하지 않는다
- 아이콘은 앵커이므로 불변. 같은 아이콘이 세로로 반복되는 가운데 제목만 조금씩 다른 상태가 v3 §7의 그림

**제안 (스키마 변경):** `ArchiveEntry`에 `day: number`를 추가해 색인에 일차를 표시한다.
일차는 상태값이지 렌더된 문장이 아니므로 §7의 "렌더 문장 미저장" 제약에 걸리지 않는다.
일기의 감각은 대부분 **날짜가 붙어 있다는 사실**에서 나온다.

## 5. L3 — 진행 오버레이 (게임이 연다)

| 오버레이 | 시점 | 대체되는 현재 요소 |
| --- | --- | --- |
| **일일 개시** | `morning` 진입 | `MorningDocument` + topbar의 `DAY 01` |
| **사무소 장면** | `event` 진입 | `EventDocument` |
| **일일 정산** | `closing` 진입 | `ClosingDocument` |
| **조우** | 조우 진입 옵션 | `EncounterView` (이미 오버레이 성격, 층만 명시) |

### 일일 개시

```
                    DAY 03
                     수요일

              제5구역 · 지시서 3건 발부

                  [ 업무 개시 ]
```

- 하루의 시작에 **한 번만** 크게. 이후 날짜는 상단 띠의 작은 칩으로만 남는다
- 발부 건수까지만 말하고 **제목 목록은 여기서 읽어주지 않는다** — 지도에서 가리켜 읽는 것이 §4다
  (현재 `START_DAY` 로그가 `— 간헐 명멸` 식으로 전 제목을 나열한다. 이 부분을 로그에서 뺀다)
- 다일 이벤트 점유 중이면 한 줄 추가 (`오늘도 약속된 일정이…`)

### 사무소 장면 — 이름을 바꾼다

`비정규 접촉 기록` / `INCIDENT MEMO` / `특이 사항 면담록` → **일과를 마치고 사무소로 돌아온 장면**으로.
사고 보고서 양식을 걷어내고 시간·장소만 준다. 스토리렛 ID는 화면에 표시하지 않는다.

이 변경 하나가 "경고가 시도 때도 없이 뜬다"는 인상을 없앤다. 빈도는 그대로 둔다 — v3 §5 기준
필수 이벤트는 잘 관리하면 전부 보이는 것이 의도다.

### 일일 정산

현재 `ClosingDocument` 유지. 처리/미처리 건수 + 정산 확정.
로그를 여기서 한 번에 보여주는 현재 구조는 맞다 (하루의 결산이므로).

## 6. L4 — 통지

`menaceWarnings()`가 내는 메나스 한계 도달을 **로그 한 줄에서 오버레이로 승격**한다.
이것이 플레이 소감에서 기대했던 "위험 수준 경고"의 자리다.

- 형식은 **본부의 공문**이다. 붉은 색·경고 아이콘·느낌표를 쓰지 않는다 —
  v3 §1의 톤 기준(*경고창·붉은 텍스트는 톤 기준 위반*)은 노후도 놀람에 대한 것이지만,
  조직이 나에게 보내는 통지 역시 조직의 언어여야 한다
- 주목 / 피로 / 동요 각각 다른 서식으로 (감사과 열람 통지 / 근무 적합성 확인 / — )
- 확인 버튼 하나로 닫고, 게임 상태는 바꾸지 않는다 (현재도 강제 이동 콘텐츠 없음)

> 동요 8의 공문 문안은 미정이다. 동요는 조직이 인지하지 못하는 축이므로 본부 공문 형식이
> 맞지 않을 수 있다. **콘텐츠 작성 시 결정** — 이 항목만 다른 형식이 되어도 무방하다.

## 7. 데이터 — 지도가 필요로 하는 것

현재 콘텐츠에 **위치 정보가 없다.** 지도를 놓으려면 지점(spot)이 필요하다.

### 구역 도면을 콘텐츠에 둔다

좌표를 지시서 템플릿에 직접 박으면 도면이 바뀔 때 템플릿이 전부 깨진다.
**도면이 지점 목록을 소유하고, 템플릿은 지점 ID만 참조한다.**

```ts
export interface ZoneSite {
  id: string;      // 'd5-w7'
  label: string;   // '7호 지선' — 표면 층이므로 조직의 언어
  x: number;       // 0~100 (도면 상대 좌표)
  y: number;
}

export interface ZoneMap {
  zone: ZoneId;
  title: string;   // '제5구역 · 시설 배치도'
  sites: ZoneSite[];
}

// ContentBundle에 추가
zoneMaps: ZoneMap[];

// WorkOrderTemplate에 추가
siteId: string;    // ZoneSite.id

// WorkOrder(바인딩 결과)에도 복사 — 리듀서는 템플릿을 재조회하지 않는다
siteId: string;
```

**빌드 검증 추가 (`core/validate.ts`):**

1. 모든 `WorkOrderTemplate.siteId`가 어떤 `ZoneMap`에든 존재할 것
2. `ZoneSite.id` 중복 없음, `x`/`y`는 0~100
3. 배치 가능한 구역(`d2`/`d5`/`d7`) 각각에 `ZoneMap`이 있을 것 — 1주차엔 `d5`만 채워도 되지만
   나머지가 비면 4주 확장 시 조용히 빈 지도가 나온다. **비어 있으면 검증 실패로 드러낸다**

WO-T1~T5 다섯 템플릿이 각각 다른 지점을 가지려면 `d5` 도면에 지점이 **최소 5개** 필요하다.
지점명은 v3 §10의 카드 내용과 맞물린다 (WO-T5 = ENC-001 = 7호 지선 하부).

### 지점명과 완곡어 축

지점명은 카드 표면이므로 원칙상 `기억` 축의 대상이 될 수 있다. **1주차에는 고정 문자열로 둔다** —
축을 하나 더 열면 판정에서 무엇이 변화를 만들었는지 분리할 수 없다.
`label: string`을 나중에 `TextVariant[]`로 넓히는 것은 파괴적 변경이 아니다.

### 아이콘 어휘 — 등록부를 고쳐야 한다

`docs/icon-vocabulary.md`의 지도 마커 항목은 `marker-main` / `marker-sub` / `marker-daily`로
**메인/서브/일상이라는 다른 분류 체계**를 쓰고 있다. `CLAUDE.md`의 아이콘 규칙은
*어휘 크기 = 표면 분류 5개와 일대일, 대응 대상은 분류 필드*라고 못박았다. **등록부가 규칙보다 오래되었다.**

교체:

| 의미 ID | 대응 `CardFace` | 표시 |
| --- | --- | --- |
| `face-inspection` | `inspection` | 점검 |
| `face-patrol` | `patrol` | 순찰 |
| `face-liaison` | `liaison` | 보고 |
| `face-supply` | `supply` | 자재 |
| `face-survey` | `survey` | 탐사 |

- `CardFace`에서 `IconId`로 가는 매핑은 **전수 매핑(exhaustive)** 이어야 하며 타입이 강제한다
- game-icons.net 파일 임포트는 **여전히 별도 라인**이다. 이번엔 절차적 SVG 5종을 폴백으로 그린다
- 마커는 **상태에 반응해 변하지 않는다.** 노후도가 오르든 재발부든 같은 아이콘 (`CLAUDE.md` 아이콘 규칙).
  처리 완료 도장만이 유일한 상태 표현이며, 그것은 아이콘이 아니라 겹쳐지는 표식이다

## 9. v3 §9 방어선 해제 기록

`docs/phase0-slice-v3.md` §9는 **지도 UI를 "별도 작업 라인, v3 판정 통과 후"로 미뤄** 두었다.
이 문서는 그 방어선을 **판정 전으로 앞당긴다.** 근거:

1. **현 화면으로는 판정 2를 측정할 수 없다.** §0에서 본 대로 카드가 전부 펼쳐져 있으면
   "여는 행위"가 없고, 측정 대상이 되는 것은 콘텐츠가 아니라 레이아웃이다
2. **판정 기록이 아직 비어 있다.** `docs/phase0-v3-playtest.md`는 전 항목 공란이므로
   지금 UI를 바꿔도 폐기되는 판정 결과가 없다. 판정을 한 번 돌린 뒤에 바꾸면 그 회차가 통째로 버려진다
3. 해제 범위는 **지도 UI에 한정**한다. 아이콘 에셋 파이프라인·2구역 운용·감류 임계 하향 등
   §9의 나머지 항목은 그대로 닫혀 있다

**판정 기준(§1의 네 목표)은 변경하지 않는다.** 화면이 바뀌어도 묻는 것은 같다.

## 12. 구현 중 사양과 갈린 지점

설계안대로 가지 않은 곳과 그 이유. 되돌릴 때 근거가 필요하므로 남긴다.

| 절 | 사양 | 실제 | 이유 |
| --- | --- | --- | --- |
| §5 | 일일 개시에 `지시서 3건 발부` 표기 | 뺐다 | START_DAY 전이라 아직 생성되지 않았다. 세어 주면 무대를 볼 이유가 그만큼 준다 — 건수는 발부 직후 로그에 남는다 |
| §1 | L2/L3 배타만 명시 | L2는 L1을 **대신**한다 | 실제로 띄워 보니 패널이 지도 아래에 붙어 고치려던 평면이 그대로 재현됐다 (규칙에 추가함) |
| §7 | `ArchiveEntry.day` 추가 여부 미결 | 추가 (SAVE_SCHEMA 4) | 일기의 감각은 대부분 날짜가 붙어 있다는 사실에서 온다. 렌더 문장 미저장 제약은 재확인 완료 |
| §6 | 동요 통지 서식 미정 | 발신처 없는 종이 한 장 | 조직이 인지하지 못하는 축이라 공문이 올 수 없다. 형식의 부재가 곧 정보다 |

부수적으로 함께 고친 것 (전부 사양 밖):

- **노후도 수치 노출** — 원장이 `제5구역 노후 5`로 값을 그대로 흘리고 있었다. v3 §9가 비공개로
  못박은 유일한 항목이라 방어선 위반. 밴드 이름으로 접었다
- **`icon-vocabulary.md`의 지도 마커 체계** — `marker-main/sub/daily`는 실제 층의 분류라
  표면 층에 둘 수 없었다. `CardFace` 5종에 일대일로 교체
- **`globals.css`의 `.district-row`** — 코드의 `.zone-row`와 어긋난 구역 리네임 잔재
- **`DATABASE_NAME = 'shattered-realm'`** — 구 프로젝트명 잔재. 스키마 4로 세이브가 버려지는 김에 교체
- **`encounter-view` → `game-view` 역참조** — `checkLabel`을 `ui-labels`로 뺐다

## 13. 아직 열려 있는 것

- **지점명 5종·통지 문안·사무소 장면 프레이밍**은 전부 **초안**이다. 문자열만 고치면 되도록
  한 군데씩에 모아 두었다 (`content.ep1-slice.json`의 `zoneMaps`, `app/notice-overlay.tsx`,
  `app/day-overlays.tsx`)
- **배치도가 비어 있다.** 격자와 마커뿐이고 시설 topology(관로가 어디로 이어지는가)가 없다.
  넣으려면 도면에 간선 데이터가 필요하다 — 지금 컴포넌트에 하드코딩하면 콘텐츠가 코드로 샌다
- **지점명의 완곡어 축.** `ZoneSite.label`은 카드 표면이므로 원칙상 `기억` 축의 대상이 될 수 있으나
  1주차에는 고정 문자열이다. `TextVariant[]`로 넓히는 것은 파괴적 변경이 아니다
- **d2/d7 도면.** 검증기가 "모든 도면은 모든 템플릿의 지점을 가져야 한다"를 강제하므로,
  추가하는 순간 지점 5개를 함께 채워야 한다 (`open-questions.md` D와 맞물린다)
