## 1. 현재 상태

- **첫 슬라이스(v1)는 기술적으로 완주했으나 플레이 판정 3항목 모두 실패.**

## 2. 판정 목표 4

1. **놀라는가** — 경고창 없이, 문장 한 자리의 차이로
2. **읽는가** — 미니게임 직후에도 산문을 읽는가
3. **재열람 서랍을 여는가** — (구: 알아채는가)
4. **금요일이 무서운가**

**1~3 실패 시 4주 사이클로 넘어가지 않는다.**

**목표 3 재정의 (2026-08-13).** 특수 카드 보류로 기억 관문이 없어 `기억`이 0에 고정된다.
문장이 한 번도 변하지 않으므로 **완곡어 인지는 측정 대상이 존재하지 않는다** —
제외로 두면 게이트 규칙이 판정 불능이 되므로, 측정 대상을 바꾼다.
이번에 보는 것은 **무료로 열어둔 재열람 서랍을 여는가**이며,
안 연다면 보류 해제 후 문장을 바꿔도 아무도 보지 않는다 —
그때는 비용 문제가 아니라 **되돌아볼 이유가 없다는 문제**이므로 다른 곳을 고쳐야 한다.
완곡어 인지(액면과 실제의 간격) 판정은 **보류 해제 후로 이월**한다.

### 새 구조에서 각 목표의 위험 지점

| 목표 | 새 위험                                                              |
| ---- | -------------------------------------------------------------------- |
| 1    | 미니게임이 놀람의 자리를 선점할 수 있다                              |
| 2    | **가장 큰 위험.** 30초 퍼즐 직후 각성 상태에서 산문을 건너뛸 수 있다 |
| 3    | 다시 열어도 같은 문장이라 **한 번 열어보고 다시는 안 열 수 있다**    |
| 4    | 평가 판정 기준 확정(§6-3) 후 위험 재평가 — 1주차는 Passed가 기본값   |

**목표 2가 이번 판정의 실질적 관문이다.** 여기서 실패하면 미니게임 도입 자체를 재검토한다.
대비책은 산문 후치와 결과 반영 분기이며, 플레이테스트 시 이 항목을 최우선 관찰한다.

기억 0 문장의 반복 노출(기준선)은 이번에 함께 깔린다 — 그 "똑같음"이 보류 해제 후
변화의 대조점이 된다. 다만 그것은 **콘텐츠 조건이지 판정 항목이 아니다.**

### v1 실패의 반대 실패

미니게임 + 특수 카드 존속이 얹히면서 **"하루가 지겹다"**는 반대 방향 실패가 가능해졌다.
하루 처리 2장 = 3~4분, 주 15~20분을 상한으로 본다. 넘으면 카드 수를 줄인다.

## 3. 검증 계획

| 회차  | 내용                                       | 확인 대상     |
| ----- | ------------------------------------------ | ------------- |
| 1회차 | 정직 플레이 (5근무일 완주 → 유임 엔딩)     | 판정 목표 1~4 |
| 2회차 | 평가를 일부러 무너뜨림 (같은 1주차 안에서) | 해고 엔딩     |

- 1회차 전 확인: 미니게임 3연타 후 산문 체류 시간, 재열람 진입 여부
- **① 단독 리뷰 시 "하루 30초" 실패 원인을 재열람 유무와 함께 본다** —
  하루가 30초로 끝난 이유 중 하나가 되돌아볼 곳이 없어서일 수 있다
- ①에서는 `기억`이 0이므로 다시 열어도 같은 문장이 나온다. 그것이 정상이며,
  그 "똑같음"이 이후 변화의 기준선이 된다

### 계측 (콘솔·스토리지 한정)

- **목표 3의 판정 지표: 재열람 서랍 개봉 횟수·시점.**
  기존 계측 항목 "재접근 횟수"가 그대로 지표가 된다 — 새 계측을 만들지 않는다
- 개봉이 1회에 그치는지, 날짜를 건너뛰며 여러 번 여는지를 구분해서 본다.
  1회 개봉은 호기심이고 반복 개봉이 습관이다. 보류 해제 후 필요한 것은 후자다
- 하루 체류 시간 · 카드 체류 시간은 기존대로 (목표 2)
- ENC-001은 최초 1회 고정이므로 발생일 기록만 남긴다 (목표 1의 유일한 매개)

### 불필요

- 서사 체인 (특수 카드 보류에 묶임 — 재개 시에도 플래그 requirements로 해결, 코드 불필요)
- 미결 더미 UI (소멸 방식 채택)
- 특수 전용 아이콘·얼굴 (특수 자체가 보류. 재개 시에도 만들지 않는 것이 승인분)

### 구현 제약 (불변)

- **렌더링된 문장을 저장하지 않는다.** 세이브 데이터에 완성된 문장이 들어가면
  재렌더가 슬그머니 보관본이 된다. 저장 대상은 문서 ID와 상태값뿐이다
- **과거 지시서에도 현재 `기억`을 적용한다.** "그때 값으로 렌더링"이 자연스러운 구현이므로
  명시하지 않으면 나중에 그쪽으로 고쳐진다. **테스트로 고정할 것**
- 조우는 하루 루프와 분리된 독립 리듀서로 유지 (향후 전환 비용 보호)
- **오버레이 타이틀(지명)은 변형 함수를 태우지 않는다.** `기억`·`노후도` 어느 축으로도
  지명이 바뀌지 않아야 한다 — 지명은 앵커다 (design-structure §1-5).
  `renderArchiveEntry`·완곡어 치환 경로에서 지명이 치환자 대상에 섞이지 않도록
  **테스트로 고정할 것**

## 8. 규칙

**판정 게이트에 도달한 코드베이스에는 기능을 추가하지 않는다.**
현재 상태가 이미 계획 범위를 초과했으므로 추가는 역효과이며,
판정 실패 시 원인 귀속이 불가능해진다.
