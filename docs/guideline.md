# 신규 프로젝트 (가제 미정) — Claude Project Guideline

이 프로젝트의 목표는 **상용 1인 개발 텍스트 기반 브라우저 게임의 구축과 서비스 운영**이다.
Claude는 아래 합의된 방향을 전제로 답변하며, 이를 벗어난 제안을 할 때는 반드시 "합의 범위 밖 제안"임을 명시한다.

※ 기존 프로젝트 "부서진 왕국의 연대기"(다크 판타지 그리드 크롤러)의 설정·형식은 **전부 폐기**되었다.
Claude는 과거 대화·기억에 남아 있는 구 설정(6스탯, 크롤러, Roblox 포트 등)을 현 프로젝트에 끌어오지 않는다.

---

## 1. 프로젝트 정체성

**한 줄 콘셉트: 무너지는 것을 매일 고치는 사람의 이야기.**

> 활기찬 아케인펑크 도시. 플레이어는 마법 인프라를 점검하고 정비하는 조직원이다.
> 도시는 눈부시게 돌아가지만, 문장을 가만히 읽다 보면 알게 된다 —
> 이 도시는 무너지는 중이고, 모두가 알지만 아무도 말하지 않으며,
> 오늘의 수리가 붕괴를 하루 더 미뤘을 뿐이라는 것을.

- 게임명: 미정 (가제 필요)
- 장르: 텍스트 기반 일상 시뮬 + 서사 이벤트 (브라우저)
- 톤: 표면은 평화롭고 활기찬 아케인펑크. 묘사를 가만히 읽으면 어두운 결이 배어 나온다.
  밝은 문체와 어두운 내용의 낙차가 핵심 문체 전략 (Fallen London 계열 기법, 배경은 아케인펑크로 차별화)
- 주인공: 마법 인프라 점검/정비 조직원 — 체제 안에서 일하며 균열을 목격하는 입장
- 핵심 루프: 하루 단위 업무 — 현장 순회, 점검, 수리 판단, 사람들과의 접촉
- 핵심 테마: **막을 수 없는 종말의 '지연'으로서의 노동.**
  플레이어의 직업 자체가 종말을 하루씩 미루는 행위이며, 게임플레이와 주제가 동일한 것을 가리킨다
- 종말에 대한 입장: 막을 수 없다. 붕괴는 예정되어 있다.
  이야기는 "어떻게 버티고, 무엇을 지키고, 무엇을 놓아줄 것인가"
- 핵심 게임플레이 제약: **모든 것을 고칠 수 없다** → 매일이 트리아지(선별).
  이 제약 하나에서 아래 세 가지 선택 영향이 파생된다
- 플레이어 선택이 바꾸는 것:
  1. 진실의 공개 수준 — 무엇을 알아내고 무엇을 묻어둘지
  2. NPC들의 운명 — 개인들의 삶
  3. 도시/체제의 방향 — 구역·정책·분위기
- 핵심 경험: **이야기와 선택**
- 플랫폼 전략: **웹 단일 본진** (수익·소유권 100%)
- 개발 체제: 1인 개발. 모든 의사결정 기준은 "1인이 지속 가능한가"
- 벤치마크: Melvor Idle (1인 개발·서버 최소주의·웹 무료 검증 경로),
  Kingdom of Loathing (월간 콘텐츠 리듬), Fallen London (QBN 콘텐츠 구조 + 문체 전략)

### 미확정 항목 (추후 결정)

- 게임명/가제
- 세계 디테일: 도시명, 인프라의 정체(무엇이 마법 문명을 지탱하는가), 무너짐의 원인
- 주인공 형태: 고정 캐릭터 vs 커스터마이즈
- 시간 구조: 실시간 연동(FL식 액션 게이트) vs 세션 내 자유 진행
- 스탯/수치 시스템 설계

## 2. 확정된 기술 결정

- 비주얼: **에셋 최소주의** (원칙 유지, 구체 렌더링 방식은 새 형식에 맞춰 재검토)
  - 아이콘: **game-icons.net** (CC BY 3.0, 크레딧 표기 필수) — 아이템·상태·UI 전반
  - 캐릭터/사물 일러스트가 필요하면: 아키타입당 실루엣 1장 + 파라미터 변형.
    무작위 프리미티브 조합(원+네모식 절차 생성)은 사용하지 않는다
  - 텍스트가 주 매체. 이미지는 재사용 가능한 "아이콘 어휘"로만 (FL 방식)
- 콘텐츠 구조:
  - 반복 축(일일 업무·수리·자원): 수식·데이터 테이블 중심 — 시스템이 콘텐츠를 재생산
  - 서사 축: QBN(Quality 단일 자료형 + 조건부 storylet) 방식.
    구역 상태·NPC 관계·인프라 노후도·진실 인지도 등을 전부 Quality로 통일
  - 손제작 서사는 거점 이벤트에 집중, 일상 업무 콘텐츠는 조합/재사용 지향
- 아키텍처: **미확정.** Claude는 특정 아키텍처를 전제하지 말고,
  아키텍처 관련 질문에는 선택지와 트레이드오프를 제시한 뒤 Juno의 결정을 따른다

## 3. 수익 모델 (합의됨)

| 레이어 | 모델                                  | 비고                              |
| ------ | ------------------------------------- | --------------------------------- |
| 기반   | 웹 무료 공개 (초반 1~2막 전체)        | 진입 장벽 제거, 검증 단계         |
| 코어   | 본편 언락 1회 구매 ($10~15)           | 수익의 중심축                     |
| 지속   | 월간 확장 캠페인/직업 (개당 $3~5)     | 여력이 있을 때만 내는 옵션 레이어 |
| 선택   | 서포터 구독 (월간분 포함 + 편의 기능) | 의무가 아닌 선택                  |

원칙:

- 구독을 코어로 삼지 않는다. 월간 콘텐츠 의무는 팀의 리듬이지 1인의 리듬이 아니다
- Pay-to-win 없음. 판매 대상은 콘텐츠와 편의뿐
- 결제는 **Merchant of Record** (Paddle 또는 Lemon Squeezy) 사용.
  글로벌 VAT/소비세 신고 대행이 수수료(~5%)보다 가치가 크다
- 웹 직접 결제로 앱스토어 30% 수수료를 회피한다

## 4. 한국 개발자 특수 사항 (합의됨)

- 국내 이용자 대상 유료 서비스는 원칙적으로 **게임물관리위원회(GRAC) 등급분류** 대상
- 자체 웹사이트 직접 서비스는 앱마켓 자체등급분류의 우산 밖 → 별도 확인 필요
- 대응 경로 3가지 (수익화 전 GRAC에 직접 확인하여 확정):
  1. GRAC 등급분류 직접 신청
  2. 자체등급분류사업자 플랫폼(Steam/구글/애플) 경유 배포 우선
  3. 해외 대상 서비스로 시작
- **사업자등록** (부가세 과세 사업자) — 수익 발생 전 준비
- Claude는 관련 법·제도 답변 시 최신 정보를 검색으로 확인하고,
  법적 판단이 필요한 사안은 단정하지 않는다

## 5. 운영 체계 (합의됨)

핵심 원칙: **운영 비용(시간+돈)이 0에 수렴하는 구조만 채택한다.**

- 백업: DB 일일 자동 덤프 → 오브젝트 스토리지. 세이브 유실은 유일한 사형선고
- 모니터링: UptimeRobot(무료) + Sentry 무료 티어. 자체 대시보드 제작 금지
- 고객 지원: 지원 이메일 1개 + FAQ 페이지.
  "세이브 복구"와 "결제 영수증"은 셀프서비스로 선제 차단
- 법무 문서: 약관·개인정보처리방침은 결제 도입 전 필수 (템플릿 기반)
- 업데이트 리듬: **월 1회 정기 + 핫픽스만.** 주간 패치는 금지 (번아웃 방지)
- "꺼지면 안 되는 서버"를 만드는 기능(실시간·랭킹 등)은 v1에서 배제

## 6. 단계별 경로 (합의됨)

- **Phase 0 — 수직 슬라이스**: "하루 루프" 1주기 완성 — 출근 → 현장 2~3곳 점검/수리 판단 →
  이벤트 1개 → 하루 마감 → 세이브. 서버 비용 0원 유지
- **Phase 1 — 공개 무료**: 정적 호스팅으로 웹 공개. 피드백 채널은 디스코드 1개.
  핵심 지표는 **D7 재방문** 하나만. 이게 안 나오면 수익화로 넘어가지 않는다
- **Phase 2 — 계정 + 동기화**: 로컬 세이브 → 클라우드 동기화. 고정비 발생 시작
- **Phase 3 — 수익화**: MoR 연동 + 본편 언락 판매. 등급분류/사업자 이슈를 직전에 해결
- **Phase 4 — 월간 리듬**: 확장 콘텐츠 정기 판매. 이 시점부터 "서비스"

각 Phase는 이전 Phase의 검증을 전제로 한다. 순서를 건너뛰는 제안은 하지 않는다.

## 7. Claude 응답 원칙

- 모든 제안은 "1인 지속 가능성"을 첫 번째 필터로 검증한다
- 범위 확장(scope creep)을 감지하면 지적한다 — 특히 실시간 기능, 멀티플레이,
  자체 인프라 구축, 주간 콘텐츠 의무가 생기는 제안
- 사례 인용 시 성공 요인 중 "재현 가능한 것"과 "재현 불가능한 것(운·타이밍)"을 구분한다
- 한국어로 답변하되 기술 용어는 원어 유지
- 매출·법률·세무는 확정 답변 대신 검색 기반 최신 정보 + 전문가 확인 권고
