# Phase 0 — 수직 슬라이스 스펙 v1

목표: **"하루 루프" 1주기가 브라우저에서 완주되고, 3일 연속 플레이 시 순환 고리가 체감되는 것.**
재미의 증명이 아니라 고리의 증명이다. (고리 = 노후도 → 지시서 → 선택 → 노후도' → 내일)

## 1. 범위

### IN
- 하루 루프 상태 기계: `morning → field → event → closing` (아래 3장)
- 3시트 상태 (스키마 최소 필드) + 순수 리듀서 코어
- Broad 판정 (주 스탯 4종) / Narrow 판정 (각인학·감류학만)
- 메나스: **피로(활성), 동요(활성), 주목(수치만 쌓이는 스텁)**
- 완곡어 시스템 최소 증명: **기억 0→1 전환 후, 동일 문서의 텍스트 변형 1곳**
- 지시서 자동 생성: 노후도 테이블 × 지시서 템플릿 3종
- 손제작 스토리렛 1개 (주인공 등장 이벤트)
- 로컬 세이브 (IndexedDB, 새로고침 후 이어하기)
- 렌더링: HTML/CSS만. 문서(지시서/보고서) 은유의 최소 UI

### OUT (Phase 0에서 하지 않음)
- 액션 게이트 (자유 진행 — 가이드라인 확정사항), 계정/동기화, 결제
- 몬스터 조우, 화염학/빙결학/공명학/증식육체론, 도감
- 고도의 시각 연출 (수치 표기만), 사운드, 다국어, 튜토리얼
- 지시서 템플릿 4종 이상, NPC 2인 이상

## 2. 하루 루프 정의

```
[morning]  노후도 테이블 → 지시서 N건 생성(슬라이스: 3건 고정) → 목록 제시
[field]    지시서 선택 → 대응 방식 선택 → 판정 → 결과 적용 → (남은 지시서 반복 or 종료)
           ※ 슬라이스에서는 3건 중 2건만 처리 가능하게 강제 (트리아지 체감 장치)
[event]    스토리렛 조건 매칭 → 1건 실행 (슬라이스: EV-001 고정 트리거)
[closing]  미처리 지시서 → 해당 구역 노후도 +1 (방치 페널티)
           전 구역 노후도 자연 틱 +1 → 고도 재계산 → 하루 요약 문서 → 세이브 → day+1
```

트리아지 강제 장치: 슬라이스에서는 "근무 시간" 카운터 2를 두고 지시서 1건 = 1 소모.
(액션 게이트의 오프라인 대역. Phase 1에서 여력 시스템으로 교체)

## 3. 판정 수식 (확정값 사용)

- Broad: `p = clamp(0.6 × stat / difficulty, 0.05, 1.0)`
- Narrow: `p = clamp(0.5 + (skill − difficulty) × 0.1, 0.1, 1.0)`
- 난수: seedable PRNG (mulberry32 등) — 리플레이·테스트 재현성 확보

## 4. 수치 초기값 (전부 튜닝 대상 — 자리표시자임을 명시)

| 항목 | 값 |
|---|---|
| 주 스탯 초기값 | 정비 40 / 진단 35 / 절차 30 / 담력 25 (신입 프로필) |
| 각인학 / 감류학 | 1 / 1 |
| 구역 수 | 3 (제2구역·제5구역·제7구역 — 가칭) |
| 구역 노후도 초기값 | 3 / 4 / 5 |
| 노후도 자연 틱 | +1/일 (전 구역) |
| 정석 수리 성공 | 노후도 −3 |
| 임시방편 성공 | 노후도 −1, `world.flags.patched_<구역>` +1 (후일 재발 훅) |
| 수리 실패 | 노후도 변화 없음, 피로 +2 |
| 고도 | `8000 − 120 × Σ노후도` (m) — 하루 요약에 숫자로만 표기 |
| 메나스 상한 | 8 (슬라이스에서는 도달 시 텍스트 경고만, 강제 이동 콘텐츠 없음) |

## 5. 완곡어 증명 시나리오 (슬라이스의 심장)

1. Day 1: 지시서 WO-T3("간헐 명멸 현상")를 액면 그대로 읽는다
2. EV-001에서 주인공의 멈춤을 목격, "묻는다" 선택 시 기억 0→1
3. Day 2: 같은 템플릿의 지시서가 생성되면 **본문 한 문단이 다르게 렌더링**된다
   (같은 데이터, memory 조건 분기 — schema의 TextVariant 참조)

이 3단계가 동작하면 완곡어 시스템의 기술 검증은 끝난 것이다.

## 6. 완료 기준 (Acceptance)

- [ ] 브라우저에서 Day 1 → Day 3까지 연속 플레이 가능
- [ ] 새로고침 후 이어하기 동작 (IndexedDB)
- [ ] 3건 중 2건 제한으로 트리아지 선택이 강제됨
- [ ] 방치한 구역의 노후도가 다음 날 지시서 난이도에 반영됨
- [ ] 기억 0→1 후 문서 텍스트 변형이 눈으로 확인됨
- [ ] 동요/피로 수치가 UI에 표시되고 이벤트로 변동함
- [ ] 판정 수식 유닛 테스트 통과 (경계값: p 하한/상한)
- [ ] 콘텐츠 빌드 검증 통과 (참조 무결성: 구역 ID, 효과 경로)

## 7. 구현 순서 (권장)

1. `schema.ts` + 리듀서 골격 + 판정 함수 (유닛 테스트 먼저)
2. 지시서 생성기 (노후도 테이블 × 템플릿)
3. 하루 상태 기계 + closing 정산
4. 콘텐츠 로더 (매니페스트 경유 — D4 규칙을 슬라이스부터 준수)
5. 문서 UI (지시서 카드 / 선택지 / 하루 요약)
6. IndexedDB 세이브 + EV-001 + 완곡어 변형 확인
